# hid_com_delay_test

测量 **pico-hid-mapper** (RP2350) 从收到控制指令到输出触屏 HID 报告的端到端延迟。

支持两种控制通道 (串口 / HID)，可对比不同链路的延迟表现。

---

## ⚠️ 测试前提 (必须满足)

### 1. 左键与右键都要映射到触屏区域

- 鼠标**左键** → 触点 0
- 鼠标**右键** → 触点 1

两者都必须在 WebUI 映射配置里设置好，否则对应动作会超时失败。

### 2. 映射类型必须是「同步按下释放」

这是最关键的一条：映射动作必须**跟随鼠标按键状态**——按下时触点按下并保持，松开时才抬起。

**不能使用**以下类型：

| 类型 | 为什么不行 |
|------|-----------|
| 连发 (自动连点) | 设备会自己反复按下/抬起，无法对应我们的按下与松开指令 |
| 单次点击 (tap) | 收到按下后立即自动抬手，测不到「松开→报告」这一步 |
| 长按 / 定时宏 | 释放时机由定时器决定，不由我们的松开指令决定 |

**程序会自动检查这一点**：启动后会按下左键并静置 400ms，若设备在此期间自发发出抬起报告，则判定映射类型不合格并报错退出：

```
映射类型自检 (按下左键后静置 400ms，检查是否有自发释放)...
  左键按下 → 报告 1.022 ms，保持中...
  自检通过: 按下保持不释放 ✓
```

失败时输出：

```
检测到自发释放报告: 左键映射类型不是「同步按下释放」(疑似连发/单次点击/长按等会自动抬手的类型)。
  请在 WebUI 映射配置中改为按下/释放跟随鼠标按键状态的类型后重试，
  否则无法测量按下与松开两个边沿的延迟。
```

## 🚀 快速开始

### 让 AI 直接帮你测

把下面这句话丢给 AI 即可 (需在仓库目录下)：

> 跑一下双 HID 的延迟测试，100 次

AI 会按 `CLAUDE.md` 里的说明自动完成：检测设备 → 开启映射 → 自检映射类型 → 跑 100 轮 → 输出统计。串口模式则说：

> 用串口跑 100 次延迟测试

### 手动运行

```bash
go build -o hid_com_delay_test .

# HID 控制 (PIO 口接上位机，Device 模式)
./hid_com_delay_test -iface hid -ctrl-vid 2e8a -ctrl-pid c9d0 \
    -target-vid 035f -target-pid 0ae8 -n 100

# 串口控制 (CH343 接 Pico UART)
./hid_com_delay_test -iface serial -serial /dev/ttyACM0 -baud 921600 \
    -target-vid 0541 -target-pid 0ce5 -n 100
```

查看全部参数：`./hid_com_delay_test -h`

## 📋 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `-iface` | `serial` | 控制接口：`serial` 或 `hid` |
| `-serial` | — | 串口路径 (如 `/dev/ttyACM0`)，`iface=serial` 必填 |
| `-baud` | `921600` | 串口波特率 |
| `-ctrl-vid` / `-ctrl-pid` | — | 控制 HID 设备 VID/PID，`iface=hid` 必填 |
| `-report-id` | `0` | 控制 HID 写入的报告 ID |
| `-target-vid` / `-target-pid` | `0541` / `0ce5` | 触屏设备 VID/PID |
| `-n` | `100` | 测试轮数 (每轮 4 个动作，共 4n 个样本) |
| `-gap` | `20` | 动作间隔 ms，过小会拥塞设备输入队列 |
| `-timeout` | `2000` | 单次等待报告超时 ms |
| `-ws` | `ws://192.168.73.1:80/ws` | 设备日志地址 (用于确认映射开关状态) |
| `-v` | `false` | 打印每条触屏报告原始内容 |

### VID/PID 会变

设备在不同控制模式下 USB 重新枚举，VID/PID 不同：

| 模式 | 触屏设备 | 控制设备 |
|------|----------|----------|
| HID 控制 | `035f:0ae8` | `2e8a:c9d0` (PIO HID) |
| 串口控制 | `0541:0ce5` | `/dev/ttyACM0` (CH343) |

用 `lsusb` 或下面的命令确认实际值：

```bash
for h in /sys/class/hidraw/hidraw*/device/uevent; do grep -H "HID_ID\|HID_NAME" $h; done
```

## 📊 输出解读

```
[001] 左按:   1.0234 ms | 右按:   1.0198 ms | 左松:   1.0265 ms | 右松:   1.0211 ms
...
===== 统计 =====
左键按下→触屏报告: n=100
  平均   1.0325 | 中位   1.0247 | 标准差   0.0889
  最小   0.7638 | P90   1.0460 | P99   1.0664 | 最大   1.8602
  直方图 (0.1ms 桶):
      1.0-  1.1 ms |  96 | ████████████████████████████████████████
```

- **平均/中位**：典型延迟；中位不受离群值影响
- **标准差**：抖动大小，越小越稳定
- **P90 / P99**：尾部延迟，反映最差 10% / 1% 的体验
- **直方图**：分布形态。单峰说明延迟稳定；多峰说明存在帧对齐分层
- **失败次数**：超时未收到报告的动作数 (正常应为 0)

## 🔧 前置准备

### hidraw 权限

普通用户读 `/dev/hidraw*` 需要 udev 规则：

```bash
sudo tee /etc/udev/rules.d/99-pico-hid-mapper.rules > /dev/null <<'EOF'
KERNEL=="hidraw*", ATTRS{idVendor}=="035f", MODE="0660", GROUP="plugdev"
KERNEL=="hidraw*", ATTRS{idVendor}=="0541", MODE="0660", GROUP="plugdev"
KERNEL=="hidraw*", ATTRS{idVendor}=="2e8a", MODE="0660", GROUP="plugdev"
EOF
sudo udevadm control --reload-rules && sudo udevadm trigger
```

### 设备日志 (可选但推荐)

程序通过 WebSocket 读取设备日志来确认映射开关状态 (`map on/off (switch key 53)`)。
若网络不通，映射切换会退化为重试并最终报错。检查方法 (需安装 websocket-client)：

```bash
pip3 install --break-system-packages --user websocket-client
python3 -c "
import websocket
ws = websocket.create_connection('ws://192.168.73.1:80/ws')
print(ws.recv())"
```

## 🩺 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| `未找到触屏设备 XXXX:XXXX` | VID/PID 不对，用上面的 `grep HID_ID` 命令确认 |
| `无法打开触屏设备: permission denied` | udev 规则未生效，执行上面的规则并 `udevadm trigger` |
| `左键按下 2s 内未收到触屏报告` | 左键未映射到触屏区域 |
| `检测到自发释放报告` | **映射类型错误**，改为「同步按下释放」类型 |
| `无法确认映射模式已开启` | WS 不通或 `~` 键未触发；检查 `-ws` 地址与映射配置 |
| 失败次数 > 0 | 动作间隔太小，增大 `-gap` (如 50) |

## 📈 实测数据

串口 vs HID 控制链路对比 (各 400 样本，Pi 5 主机)：见 [RESULTS.md](RESULTS.md)。

| 链路 | 平均 | 中位 | 标准差 | P99 |
|------|------|------|--------|-----|
| HID 控制 | **1.029 ms** | 1.026 | **0.048** | 1.066 |
| 串口 921600 | 1.559 ms | 1.577 | 0.338 | 2.018 |

HID 链路 97.5% 的样本落在 1.0–1.1 ms（即一个 USB 全速帧周期）内，延迟稳定；串口链路呈 0.8/1.4/1.8 ms 多层分布。

## 🔬 工作原理

```
上位机 ──控制帧──> Pico (映射引擎) ──触屏 HID 报告──> 上位机 hidraw
   │ t0                                                    │ t1
   └──────────── 延迟 = t1 − t0 ─────────────────────────┘
```

1. 定位触屏 hidraw 与控制链路 (均按 USB VID:PID 匹配 sysfs)
2. 发送 `~` (KEY_GRAVE) 开启映射，通过设备 WS 日志 `map on (switch key 53)` 确认
3. **映射类型自检**：按下左键静置 400ms，确认无自发释放
4. 循环 `-n` 轮，每轮 4 个动作：左按下 → 右按下 → 左松开 → 右松开
   (buttons 位掩码 `0x01 → 0x03 → 0x02 → 0x00`，每步恰好一个按键边沿)
5. 每步记录写入完成时刻 t0，等待匹配的触屏报告 (触点 ID + tip 位 + 压力值匹配)，
   读取时刻 t1，延迟 = t1 − t0
6. 关闭映射，输出统计

**实现要点**：触屏 hidraw 由专用 goroutine 持续读取。设备每个动作会发重复报告，
若只在测量窗口内按需读取，残留报告会填满内核 hidraw 环形缓冲 (64 条)，
之后内核静默丢弃新报告，表现为 ~10% 的假超时。
